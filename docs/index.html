Conditional Encryption

with Applications to Secure Personalized Password Typo Correction

Conditional Encryption extends public-key encryption with a conditional encryption algorithm. A payload decrypts only when an encrypted hidden message satisfies a predicate with respect to a control message. If the predicate does not hold, the payload remains hidden even from an adversary who has the secret decryption key.

Overview

What the artifact contains

This page accompanies the ACM CCS 2024 paper Conditional Encryption with Applications to Secure Personalized Password Typo Correction. The artifact includes a C++ implementation of Conditional Encryption, predicate families such as equality, edit distance, Hamming distance, CAPSLOCK, and OR composition, performance-evaluation scripts for reproducing the paper’s figures and tables, and an application to TypTop for privacy-preserving typo-tolerant password checking.

Core idea

Encrypt under a condition

Let c1 = Enc(pk, m1) be a ciphertext for a hidden message m1. Conditional Encryption computes c = CEnc(pk, c1, m2, m3), where m2 is a control message and m3 is a payload.

  • If P(m1, m2) = 1, the conditional ciphertext decrypts to m3.
  • If P(m1, m2) = 0, the ciphertext hides m2 and m3.
  • The security goal remains meaningful even when the adversary has the decryption key.

Why this matters

Private checks without revealing the checked value

Many security systems need to test whether a hidden value satisfies a condition without revealing that value. Conditional Encryption supports this pattern while preserving formal security guarantees and remaining close to implementation.

Application

Conditional TypTop

TypTop accepts plausible password typos while helping users avoid repeated failed logins. Conditional Encryption strengthens this setting: the server can check whether a submitted password is a permitted typo without collecting ciphertexts for unrelated password attempts.
